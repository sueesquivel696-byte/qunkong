# 后续开发任务池

## 目的

本任务池用于后续维护排期。每次只选择一个小任务执行，不顺手扩大范围。

## A 类：必须保持稳定

| 任务 | 当前状态 | 优先级 | 验收方式 |
|---|---|---|---|
| 本地无授权启动 | 已可用 | 最高 | 双击本地无授权版能进入主界面 |
| 旧第三方域名阻断 | 已有检查脚本 | 最高 | `node scripts/check-blocked-domains.js` 通过 |
| 店铺列表和登录态 | 已有功能 | 高 | 店铺列表可见，登录态不丢失 |
| 订单同步和缓存 | 已有后端链路 | 高 | 能读取/缓存订单，不泄露凭据 |
| 商品同步和云商品库 | 已有后端链路 | 高 | 能同步商品，本地云商品库可用 |
| 数据看板缓存 | 已有后端链路 | 高 | 数据刷新和缓存健康可查 |
| GitHub 主分支维护 | 已接入 | 高 | 每次修改提交并推送 `main` |

## B 类：安全加固任务

| 任务 | 说明 | 建议顺序 |
|---|---|---|
| 高风险操作二次确认 | 覆盖商品、订单、发货、删除、发布 | 1 |
| 操作预览机制 | 发布/删除/补发前显示影响范围 | 2 |
| 任务日志统一化 | 记录任务 ID、目标、数量、结果 | 3 |
| 敏感信息脱敏 | 凭据、Cookie、token 不进入日志/文档 | 4 |
| 导出文件提示 | 订单/财务/商品导出后提示敏感 | 5 |

## C 类：前端重建任务

| 页面 | 原打包文件线索 | 建议优先级 | 原因 |
|---|---|---|---|
| 店铺列表 | `ShopList-*.js` | 1 | 入口功能，风险相对可控 |
| 数据概览 | `DataOverview-*.js` | 2 | 高频只读页面，可建立组件规范 |
| 订单管理 | `OrderManagement-*.js` | 3 | 重要但涉及敏感数据 |
| 商品管理 | `ProductManagement-*.js` | 4 | 重要且高风险，需要保护层 |
| 云商品库 | `CloudProductLibrary-*.js` | 5 | 本地业务数据较多 |
| 发布任务 | `CloudPublishTasks-*.js` | 6 | 高风险批量操作 |
| 财务/成本 | `FinanceManagement-*`、`ProductCostManagement-*` | 7 | 涉及经营数据 |
| 广告/数据罗盘 | `AdPromotionManagement-*`、`DataCompass-*` | 8 | 依赖外部数据接口 |
| 素材中心 | `MaterialCenter-*` | 9 | 可后置 |

## D 类：后端整理任务

| 模块 | 文件范围 | 目标 |
|---|---|---|
| 店铺和会话 | `shopManager.js`、`shopStore.js`、`shopBrowserManager.js`、`sessionService.js` | 明确登录态和用户数据保护边界 |
| 订单 | `controllers/orderManager.js`、`services/orders/*` | 明确凭据、同步、补发链路 |
| 商品 | `controllers/productManager.js`、`services/products/*` | 拆清同步、云库、发布任务 |
| 数据看板 | `syncManager.js`、`services/shopData/*` | 统一缓存、刷新队列和失败处理 |
| 财务/成本 | `finance/*`、`productCost*` | 提高核算逻辑可解释性 |
| 诊断日志 | `diagnosticLogger.js`、`structuredLogger.js` | 统一脱敏和导出规则 |

## E 类：暂不恢复

| 功能 | 原因 | 恢复条件 |
|---|---|---|
| 旧授权服务器 | 非公司可控 | 不恢复 |
| 旧 AI 作图/文案 | 非公司可控 | 接入公司自有 API 后重做 |
| 旧快递提号接口 | 非公司可控 | 接入公司自有 API 后重做 |
| 直接编辑打包前端 | 易白屏，难维护 | 重建源码后替代 |

## 每次任务执行规则

1. 先读 `AGENTS.md`、`README.md`、`PROJECT_SPEC.md` 和相关功能文档。
2. 一次只做一个明确任务。
3. 修改前确认影响范围。
4. 修改后运行相关检查。
5. 只提交本次相关文件。
6. 推送 GitHub `main`。

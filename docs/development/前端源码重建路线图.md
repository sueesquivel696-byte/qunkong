# 前端源码重建路线图

## 背景

当前前端位于：

```text
app/dist
```

它是 Vue 打包产物，不是原始 `.vue` 源码。历史记录显示，直接修改打包 JS 曾导致白屏。因此后续如果要长期维护页面，应逐步重建前端源码，而不是继续手改 `app/dist/assets/*.js`。

## 目标

逐步建立可维护的前端源码目录，例如：

```text
src/
```

并最终让页面从源码构建生成 `app/dist`。

## 重建原则

1. 先保留当前运行版，不破坏 `local-noauth-build`。
2. 每次只重建一个页面或一个公共组件。
3. 新页面先对接现有 `window.electronAPI`，不同时大改后端。
4. 对高风险按钮先只做只读展示或禁用，确认保护逻辑后再启用。
5. 每个页面重建后都要有截图/页面验证和功能清单。

## 建议技术路线

建议使用：

- Vue 3
- Vite
- Element Plus
- Electron preload 暴露的 `window.electronAPI`

当前后端已经通过 `preload.js` 暴露了大量 API，前端重建时优先复用这些接口。

## 页面重建顺序

### 第一批：低风险入口页

1. 店铺列表 `ShopList`
   - 功能：店铺展示、分组展示、登录状态展示。
   - 初期禁用：删除店铺、重登、批量登录等高风险按钮。
   - 验收：能显示店铺列表和基础状态。

2. 数据概览 `DataOverview`
   - 功能：展示缓存数据、缓存健康、刷新状态。
   - 初期限制：刷新动作增加确认或只对单店测试。
   - 验收：能读取缓存并展示基础卡片。

### 第二批：重要只读/导出页

3. 订单管理 `OrderManagement`
   - 先实现：订单缓存列表、筛选、只读详情。
   - 后实现：同步、导出、OpenAPI 凭据保存。
   - 高风险：凭据保存、补发相关操作必须后置。

4. 财务/成本 `FinanceManagement`、`ProductCostManagement`
   - 先实现：只读统计和成本列表。
   - 后实现：SKU 绑定、成本配置保存、删除。

### 第三批：商品和发布

5. 商品管理 `ProductManagement`
   - 先实现：商品缓存列表和只读详情。
   - 后实现：同步、打开编辑页。
   - 最后实现：批量下架。

6. 云商品库 `CloudProductLibrary`
   - 先实现：本地库列表、详情、导入导出。
   - 后实现：删除、审核、编辑草稿。

7. 发布任务 `CloudPublishTasks`
   - 必须先有任务保护层。
   - 必须显示目标店铺、商品数量、队列状态、失败明细。

### 第四批：扩展页

8. 广告推广 `AdPromotionManagement`
9. 数据罗盘 `DataCompass`
10. 限时抢购 `FlashSaleManager`
11. 素材中心 `MaterialCenter`

## 公共组件建议

优先沉淀：

- 店铺选择器。
- 店铺分组选择器。
- 风险操作确认弹窗。
- 任务状态表格。
- 错误详情面板。
- 导出文件提示组件。
- 空状态和加载状态组件。

## 验收标准

每重建一个页面，必须满足：

1. 不影响当前可运行版本。
2. 不调用旧第三方接口。
3. 不泄露 Cookie/token/凭据。
4. 高风险按钮默认受保护。
5. 有对应文档记录：页面入口、使用的 API、风险点、验证方式。

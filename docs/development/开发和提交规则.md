# 开发和提交规则

## 主维护目录

```text
E:\桌面\新建文件夹\wechat-shop-automation-rebuild
```

## 当前远程仓库

```text
https://github.com/sueesquivel696-byte/qunkong.git
```

默认分支：`main`。

## 推荐开发入口

双击：

```text
E:\桌面\新建文件夹\wechat-shop-automation-rebuild\开发命令行.bat
```

该脚本会把便携 Git 和 Node.js 加入 PATH。

## 每次开发前

执行：

```powershell
git status --short --branch
git pull --rebase
```

确认工作区干净，且本地基于最新 `origin/main`。

## 每次修改范围

允许修改：

- `app/electron/`
- `app/shared/`
- `scripts/`
- `docs/`
- `README.md`
- `PROJECT_SPEC.md`
- `CHANGELOG.md`
- `AGENTS.md`
- `package.json` / `package-lock.json`（仅在依赖确实变化时）

默认不修改：

- `app/dist/`
- `local-noauth-build/`
- `runtime/`
- `node_modules/`
- `tools/`
- `final-backups/`
- `recovered-source/`
- `app_asar_unpacked/`

如必须修改运行产物或打包前端，必须先说明原因、备份方式和验证方案。

## 禁止提交

- 用户数据和备份。
- Cookie、token、secret、OpenAPI 凭据。
- `.env`、`app-auth.json`。
- 日志、截图、zip 备份。
- `exe/dll/pak/bin/dat/asar` 等运行产物。
- `node_modules`。

## 每次验证

至少执行：

```powershell
node scripts/check-blocked-domains.js
git status --short
```

如果改了业务逻辑，还需要补充对应验证：

- 店铺：检查店铺列表和登录态。
- 订单：检查同步/缓存/导出，不泄露凭据。
- 商品：检查同步/发布/下架的保护逻辑。
- 数据看板：检查刷新队列和缓存健康。
- 文档：检查路径和结论是否对应真实文件。

## 提交规则

每次只提交本次任务相关文件：

```powershell
git add <本次相关文件>
git status --short
git commit
```

提交说明必须包含：

```text
简短标题

本次修改：
- xxx

修改原因：
- xxx

验证方式：
- xxx

遗留问题：
- 暂无已知遗留问题
```

## 推送规则

提交后推送：

```powershell
git push
```

推送完成后确认：

```powershell
git status --short --branch
```

应显示本地与 `origin/main` 同步。

## 回滚规则

如果已经提交但未推送：

```powershell
git reset --soft HEAD~1
```

如果已经推送，默认不强推覆盖，应该新增修复提交。只有明确确认要恢复历史时，才允许使用回滚或强推方案。

## 高风险操作开发规则

凡涉及以下功能，必须先参考：

```text
docs/safety/高风险功能保护清单.md
```

包括：

- 商品发布。
- 批量下架。
- 补发订单。
- 保存凭据。
- 删除类操作。
- 财务/成本配置。

# 06-后续维护开发建议

## 当前可维护重点

优先维护：

```text
app/electron
app/shared
scripts
README.md
PROJECT_SPEC.md
CHANGELOG.md
AGENTS.md
docs/function-exploration
```

暂不建议直接维护：

```text
app/dist
local-noauth-build
app_asar_unpacked
recovered-source
final-backups
tools
node_modules
runtime
```

## 建议的开发顺序

### 第一阶段：稳定基线

1. 保持本地无授权启动可用。
2. 保持旧第三方域名阻断。
3. 完善文档和功能地图。
4. 每次修改后运行：

```powershell
node scripts/check-blocked-domains.js
git status --short --branch
```

### 第二阶段：后端服务可维护化

优先整理 `app/electron/services` 中最重要的链路：

1. 店铺和登录态。
2. 订单同步和订单缓存。
3. 商品同步和云商品库。
4. 商品发布任务队列。
5. 财务/成本。
6. 广告/数据看板。

每次只改一个小功能，不顺手重构无关文件。

### 第三阶段：重建前端源码

当前前端只有打包产物。建议新建真正可维护的前端源码目录，例如：

```text
src/
```

按页面逐步重建：

1. 店铺列表。
2. 数据概览。
3. 订单管理。
4. 商品管理。
5. 云商品库和发布任务。
6. 财务/成本。
7. 广告和数据罗盘。

不要直接大规模修改 `app/dist/assets/*.js`。

### 第四阶段：高风险操作加保护

对这些操作增加统一保护：

- 批量下架商品。
- 发布商品到店铺草稿。
- 批量发布任务。
- 补发/发货类操作。
- 保存 OpenAPI 凭据。
- 删除店铺/商品/任务记录。

建议保护方式：

- 测试模式。
- 操作预览。
- 二次确认。
- 限速和队列暂停。
- 失败日志。
- 操作记录导出。

## GitHub 使用规则

当前主分支为 `main`，远程为：

```text
https://github.com/sueesquivel696-byte/qunkong.git
```

后续默认提交：

- 源码。
- 脚本。
- 文档。
- 安全策略。
- 不含敏感信息的报告。

默认不提交：

- 运行产物。
- 日志。
- 截图。
- 备份包。
- 用户数据。
- Cookie/token/secret/credential。

## 每次任务验收格式

每次完成后至少记录：

1. 改了哪些文件。
2. 为什么改。
3. 如何验证。
4. 是否推送 GitHub。
5. 遗留风险。

## 当前遗留问题

1. 前端原始 Vue 源码未恢复。
2. 运行版和主工程之间仍存在“源码/产物同步”关系，需要后续明确打包流程。
3. AI 作图/文案、快递提号等第三方扩展仍禁用，未接入公司自有接口前不能恢复。
4. 高风险真实业务操作缺少统一测试模式和二次确认策略。

# 02-启动入口和运行链路

## 推荐启动方式

当前推荐启动：

```text
E:\桌面\新建文件夹\local-noauth-build\微信小店多店铺群控.exe
```

或使用项目内脚本：

```text
E:\桌面\新建文件夹\wechat-shop-automation-rebuild\run-local.bat
```

也可以用 Node 启动脚本：

```powershell
node scripts/start-local.js
```

## 启动脚本差异

| 入口 | 状态 | 说明 |
|---|---|---|
| `run-local.bat` | 推荐 | 切到 `local-noauth-build` 并启动 exe |
| `scripts/start-local.js` | 推荐 | 用 Node spawn 启动同一个 exe |
| `启动群控软件-本地无授权版.bat` | 可用 | 顶层无授权启动入口，指向本地无授权运行产物 |
| `启动群控软件-本地授权.bat` | 旧链路 | 可能依赖本地授权服务，仅作历史参考 |
| `启动本地授权服务.bat` | 旧链路 | 启动本地授权服务，不是当前推荐入口 |
| `旧版不要使用-会走原授权逻辑.lnk` | 禁用 | 文件名已提示会走原授权逻辑 |

## Electron 主进程入口

项目入口：`package.json` 的 `main` 指向：

```text
app/electron/main.js
```

应用包入口：`app/package.json` 的 `main` 指向：

```text
electron/main.js
```

## 本地无授权逻辑

`app/electron/main.js` 中注册了本地授权管理对象，`get-app-auth-status` 返回本地已授权状态。当前版本目标是不依赖旧授权服务器。

相关文件：

- `app/electron/main.js`
- `app/electron/ipc/appAuthHandlers.js`
- `app/electron/services/appAuthConfig.js`

## 前端加载

前端当前来自打包目录：

```text
app/dist/index.html
app/dist/assets/*.js
```

注意：`app/dist` 是打包产物，不是原始 Vue 源码。README 记录过历史上直接用 PowerShell 读写打包 JS 曾导致白屏，因此后续不建议直接改压缩后的前端产物。

## 日志和诊断

诊断相关文件：

- `app/electron/services/diagnosticLogger.js`
- `app/electron/ipc/diagnosticHandlers.js`
- `app/electron/services/networkCaptureLogger.js`
- `reports/security-scan-20260627.md`

诊断 IPC 包括：

- `write-diagnostic-log`
- `export-diagnostic-logs`
- `open-diagnostic-export-dir`
- `open-debug-session`

## 风险提醒

- 不要使用旧版快捷方式。
- 不要随意运行 `以管理员运行-阻断旧外部服务器.ps1`，它可能修改系统 hosts 或网络设置。
- 不要在未确认测试账号/测试店铺前点击真实发布、发货、删除、改价等按钮。
